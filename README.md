# 教材履约台（培训教材发放与补发）

学员报名后，按 **班级 × 教材版次 × 收货地址 × 开课时间** 自动生成备货清单；
覆盖拣包、交运、签收、改地址、版次升级补充、错寄/拒收/破损补发、退课拦截全流程。

- 仅依赖 Python 3.10+ 标准库（`http.server` + `sqlite3`），无外部服务
- 履约状态存本地 SQLite（`data/fulfill.db`），签收图存本地文件（`data/proofs/`）
- 物流由内置模拟接口按运单号回传（揽收/派送/签收图/拒收退回）

## 一条命令启动

```bash
./run.sh            # 重置演示数据（含错版案例）并启动 → http://127.0.0.1:8000
./run.sh --keep     # 保留数据启动
./run.sh test       # 只跑规则测试
PORT=8010 ./run.sh  # 换端口
```

## 业务规则落点

- **首次发放唯一**：`parcels` 部分唯一索引 `(enrollment_id) WHERE kind='first'`，
  一个报名记录只能创建一次首包。
- **版次规则**：升级时未交运包裹自动换版（旧版回库、新版扣库）；
  已寄旧版只追加 `supplements` 补充资料（含文字版次差异说明），
  `parcel_items.edition` 是寄出快照，永不回写。
- **地址截止**：只要存在 `shipped/delivered/rejected/returned` 包裹，
  申请与审批两道关卡都拒绝改地址；申请后、批准前恰好交运的，批准时自动驳回。
- **补发幂等**：异常单有 `idem_key(parcel_id,type)` 唯一约束，
  补发包裹对 `exception_id` 唯一；已获批补发的包裹不能再次登记异常。
- **职责分离**：仓库角色不能审批任何异常；任何人不能审批自己提交的异常单。
- **库存竞争**：扣库用条件 `UPDATE ... WHERE qty >= ?`，
  高并发下恰好一个成功、一个报库存不足，不会超卖、库存不会为负。
- **退课拦截**：有在途/已签收包裹禁止退课；未交运包裹取消并回库，
  待审异常、地址申请一并关闭。
- **拒收**：模拟回传 rejected 后包裹退回入库，可再走异常补发。
