# 教材履约系统

学员报名后，教材按**班级、教材版次、收货地址、开课时间**自动生成备货清单；
覆盖仓库拣书打包、前台发货/签收跟踪、学员改地址与补发申请的完整履约链路。

纯 Python 标准库实现（`http.server` + `sqlite3`），无外部依赖、无需安装。

## 单条命令启动

```bash
./run.sh            # 默认 8000 端口，自动建库并写入种子数据（含错版案例）
# 或
python3 app.py --port 8000 --reset
```

打开 http://localhost:8000 ，右上角切换身份：

| 身份 | 账号 | 可见功能 |
|---|---|---|
| 仓库 | `wangc` / `liku` | 待发列表、拣包单、拣货扣库存、交运、库存、签收图 |
| 前台 | `zhaoq` | 物流跟踪、改址/补发审批、发放补充资料、退课 |
| 学员 | `chen` 等 | 仅本人包裹与物流、签收凭证、申请改址/补发 |

## 页面与交付物

- **班级发放计划** `/plan`：每班教材版次、发放进度；版次升级后的「补充资料清单」。
- **待发列表** `/pending`：按**开课倒计时**升序，逐单显示**缺书数量**；库存不齐时拣包单不出现拣货按钮。
- **拣包单** `/shipment?id=N`：该单教材版次/ISBN、拣货勾选、库存缺口、交运地址快照、物流轨迹、签收凭证。
- **物流跟踪** `/tracking`：前台查看发货与签收，签收图为本地文件。
- **审批中心** `/approvals`：异常补发审批、改址审批、退课办理。
- **教材库存** `/inventory`：按版次的库存与流水（拣货/退回/补货）。
- **学员端** `/student`：只展示本人包裹，**不出现仓库内部备注**；版次差异以文字说明呈现。

## 内置案例（种子数据）

| 学员 | 场景 |
|---|---|
| 陈学员 | 旧版**已签收** → 版次升级生成补充资料（历史不抹）；交运后改址，仅对后续补发有效 |
| 林学员 | 待发包裹遇版次升级，明细自动换新版；新版期初库存 0，待发列表显示**缺 1 本** |
| 黄学员 | 错寄异常由王仓提交，**王仓本人无法审批**，须李库或前台处理 |
| 周学员 | 物流拒收 → 包裹退回、图书回库 → 审批后生成补发 |
| 吴学员 | 包裹破损异常待审批 |
| 郑学员 | 已有一次补发签收，再报「重复补发」→ 审批只登记结案，不再发书 |
| 孙学员 | 开课前退课：未交运包裹取消、已拣图书回库、待审批单自动驳回 |

模拟物流：交运生成运单号，页面按钮回传 `运输中/派送中/已送达/拒收`；
签收时在 `data/signatures/` 生成 SVG 签收图。

## 核心业务规则

1. **首次发放唯一**：一个报名记录只能有一条 `initial` 包裹；应用层与 SQLite
   部分唯一索引（`WHERE kind='initial'`）双重兜底，并发创建只有一个成功。
2. **改地址截止**：审批通过时若存在待发（未交运）包裹，直接更新其地址；
   包裹一旦交运，地址快照冻结，新地址只对之后新建的补发生效。
3. **版次升级**：未交运包裹明细换成新版；已寄旧版只追加补充资料记录与补发，
   旧包裹、旧版明细、旧签收凭证原样保留。
4. **补发审批与幂等**：必须填写理由并经审批；每张异常单最多产生一条补发
   （`idempotency_key = exc-<单号>` 唯一约束）；仓库人员不能批准自己提交的异常；
   「重复补发」类只登记结案。
5. **库存竞争**：拣货在 `BEGIN IMMEDIATE` 事务内按
   `UPDATE ... SET qty=qty-? WHERE qty>=?` 原子扣减，任一品种不足整单回滚；
   并发两单抢最后一本，恰有一单成功，库存绝不为负。
6. **退课拦截**：未交运包裹取消并回库、待审批改址/异常自动驳回；
   已交运包裹保留物流轨迹，一切新补发（含补充资料）被拦截。
7. **错寄 / 拒收 / 破损 / 重复补发**分别走异常类型与审批流；拒收自动退回入库。

## 测试

```bash
python3 -m unittest tests -v
```

25 个用例覆盖：版次规则（换版/补充/幂等）、地址截止（交运前后）、
补发幂等与自审批禁止、库存竞争（多线程抢最后一本）、退课拦截、
首次发放并发唯一、拒收回库、状态机非法跃迁、重复签收。

## 文件结构

```
db.py         SQLite schema（含部分唯一索引、CHECK 约束）
services.py   全部业务规则（FulfillmentService）
logistics.py  模拟物流：运单号、签收图 SVG
seed.py       种子数据（含错版案例）
app.py        http.server Web 界面（仓库/前台/学员三视图）
tests.py      业务规则测试
run.sh        单条命令启动
data/         运行时：fulfillment.db + signatures/（git 忽略）
```
